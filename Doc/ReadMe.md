# 外设

## I2C总线和I2C外设
1. **I2C事务问题**
    - 一次I2C事务是开始信号和停止信号之间的所有操作

## SPI总线和SPI外设
### SPI特性
    - 基于三条线的全双工同步传输
    - 基于双线的单工同步传输
    - 支持8位或16位传输帧格式: 数据寄存器是16位, 同时用于发送和接收
### SPI flash
1. **读->修改->写入**
    - 由于flash写入前需要进行擦除(按扇区)
    - 安全写入方法: 把扇区内容读取到内存中, 对需要修改的数据进行修改, 擦除扇区, 把内存数据重新写入扇区
2. **flash时许问题**
    - 对于有些flash, 命令是存在时序限制的, 比如写入命令, 命令+写入数据, 必须在一个事务中完成, 否则就会命令执行失败的情况

### FSMC: Flexible Static Memory Controller
1. **核心概念**
    - 两个专门的控制器
        - NOR Flash控制器: 管理SRAM、ROM、NOR Flash、PSRAM
        - NAND/PC卡控制器
    - 地址映射
        - 1GB: 4个存储区域, 每个块256MB, 每个存储块细分为4个子块, 对应独立的片选信号
    - 关键存储器参数: 地址建立时间, 数据保持时间
2. **一些参数**
    - 同步访问
        - 突发访问: 同步存储器, 突发模式允许在发出起始地址后连续传输多个数据，提高传输速率
        - 等待信号极性: 等待信号的有效电平
        - 环绕模式: 当突发访问地址达到边界时自动回绕到起始地址
        - 等待信号有效时间: 指定等待信号是在等待状态前一个时钟周期有效，还是在等待状态期间有效
        - 写突发操作: 
    - 异步访问
        - 异步等待时间: 异步存储器（如较慢的NOR Flash）可通过等待信号通知控制器延长访问时间
3. **应用场景**
    - 扩展大容量内存
    - 驱动大容量存储: 通过NAND Flash控制器连接大量NAND Flash芯片
    - 直连液晶显示屏

### 显示屏
1. **种类**
    - LCD
    - LED: 像素体积大
    - OLED: 电视, 手机, 手表普遍使用
2. **LCD**
    - 硬件组成
        - 主控芯片 ---(8080/SPI)---> 液晶控制器芯片(显存) ---(RGB接口)---> 液晶面板
        - 信号线
            - RBG信号线: 红绿蓝
            - 像素同步时钟信号: 液晶屏与外部使用同步通讯方式
            - 水平同步信号: 液晶屏一行数据传输结束, 电平发生跳变
            - 垂直同步信号: 液晶屏一帧数据传输结束, 像素发生跳变
            - 数据使能信号： RGB信号数据有效
3. **驱动**
    - 硬件初始化
    - 寄存器初始化
    - GRAM扫描模式: 定义像素扫描的起点和方向, x轴的起点和方向, y轴的起点和方向; 起点有4个, 方向有2个, 总共8种扫描模式
    - 打开窗口: 在显示器上开辟一个窗口, 参数是x轴的起点和终点, y轴的起点和终点
    - SetCursor: 设置光标坐标. 在指定坐标点(x,y)开辟一个像素宽度和高度为1的窗口
    - FillColor: 填充指定像素点数量颜色. 从 Start Column和Start Page坐标点开始填充指定数量, 指定颜色的像素点
    - ClearWindow: 清空窗口. 打开窗口, 填充颜色(OpenWindow + FillColor)
    - SetPointPixel: 对像素点进行颜色填充. 设置光标坐标, 填充颜色(SetCursor + FillColor)
    - ReadPixelData: 读取一个像素数据. 从 Start Column和Start Page坐标点开始读取一个像素数据
    - GetPixelData: 获取显示器上某一个坐标点的数据. 设置光标坐标, 读取像素数据(SetCursor + ReadPixelData)

        - DrawCircle: 画圆.
    - 字符显示: 输入待显示字符, 根据字符获取字模, 把字模数据写入指定窗口
        - DisplayChar: 显示英文字符. 开一个窗口, 然后把字模的像素数据写进去(OpenWindow + SetPixel)
        - DisplayStringLine: 在指定行显示英文字符串. 计算每个英文字符显示的位置, 在这个位置上开一个窗口, 然后把字模数据写进去
        - DisplayString: 在任意位置显示英文字符串. 计算每个英文字符显示的位置, 在这个位置上开一个窗口, 然后把字模数据写进去
        - DisplayStringYDirection: 沿着Y轴方向显示英文字符串. 
        - DisplayCharChina: 显示中文字符. 开一个窗口, 然后把字模的像素数据写进去
        - DisplayStringLineChina: 
        - DisplayStringChina: 
        - DisplayStringYDirectionChina: 
        - DisplayStringYDirectionChina: 
        - DisplayStringLine_EN_CH: 显示中英文字符串. 英文字符的编码是0-126; 中文字符为了兼容英文, 表示中文字符时, 最高位为1
    - 字体

        - DisplayCharEx: 利用缩放后的字模显示字符
        - DisplayStringEx: 利用缩放后的字模显示字符串
        - DisplayStringExYDirection: 沿Y轴方向显示
        - SetFont

# 中间件

## 文件系统
1. **基本概念**
    - 定义: 组织、存储、管理和检索存储设备上的数据的软件
2. **单设备(U盘/SD卡)文件系统**
    - 文件系统元数据(文件位置, 目录结构等)和数据存储在同一个设备上
    - 组成
        - 超级块: 存储整个文件系统的元数据
        - Inode表: 存储inode的固定区域, 每个inode是文件或目录的元数据容器
        - 数据块区域: 存储文件实际内容和目录内容的物理空间
        - 块位图/Inode位图: 高效跟踪空闲资源. 0表示空闲, 1表示占用
        - 目录结构: 提供用户和程序可见的层级命名空间
3. **嵌入式文件系统选择**
    - 只读文件系统
        - Cramfs: 页级压缩; 支持随机访问; 需要解压到RAM运行 —— 适合Linux的根文件系统
        - SquashFS: 高压缩率; 挂载时动态解压, 访问速度快 —— 适合android系统分区, IOT设备固件映像
        - RomFS: 支持XIP(可直接在flash执行代码); 无压缩 —— 适合bootloader或内核镜像存储
    - 基于RAM的文件系统
        - tmpfs: 动态分配内存; 支持交换分区缓存
        - Ramdisk: 固定内存模拟为快设备, 需要预先分配内存; 空间不足需要重新格式化、
    - 闪存优化文件系统
        - JFFS2: NOR/NAND Flash, 日志结构, 压缩存储, 均衡磨损
        - YAFFS2: NAND Flash, 煤业自带OOB元数据管理, 坏块处理高效, 无压缩
        - UBIFS: 大容量NAND Flash, 基于UBI卷管理, 支持动态磨损均衡
        - SPIFFS: SPI NOR Flash, 低内存占用; 适合小文件存储
    - 轻量可读写文件
        - LittleFS: 日志结构 + COW(Copy-on-Write); 内置磨损均衡
        - FATFS: 兼容性好; 需要自行实现底层驱动diskio.c
            - FAT16/FAT32: 兼容性好; 无日志功能; 无权限控制; 存在文件大小限制
            - exFAT: 最大支持16EB大文件; 轻量级日志; 无权限控制
    - 网络文件系统
        - NFS: 通过网络远程挂载目录, 简化开发调试
    - ext4(Linux主流)
        - 特点： 日志式文件系统; 16TB单文件, 1EB分区; 延迟分配技术(减少碎片); 权限控制

4. **HardFault_Handler**
    - 根据不同的CPU类型进行编写: 可以参考FreeRTOS中的portable文件
    - 关于SP指针
        - SP指针(对于CortexM4来说, 寄存器R13)
        - 此时如果把SP指针的值移动到R0中, 并调用一个需要一个入参的打印函数
        - 对于函数而言, 入参存放的位置从左到右的顺位如下: r0, r1, r2, r3, 栈
        - 所以, 入参的值就是r0的值, 打印r0所指向内存的值就是当前栈中存放的数据
        - 以栈底为界限, 把栈中的数据都打印出来, 就能看到当前的调用轨迹
        - 如果通过指令和数据的存储分布进行分析, 还能把函数调用的轨迹打印出来
    - PC指针的使用
        - fromelf.exe -c --text --output list.txt .\WD001.axf: -c, disassemble code
        - 使用ARMCC编译器执行目录下的fromelf把可执行文件.axf反汇编, 然后根据堆栈信息查找崩溃的原因

5. **关于堆和栈**
    - 在MCU中, 栈是向上增长的, 堆是向下增长的
    - __initial_sp, __heap_limit, __heap_base, 这三个变量定义了栈底, 堆的范围
    - 找到栈的范围和堆的范围
        - 确保栈不会溢出到堆中
        - 在MCU中, 栈是向上增长的, 堆是向下增长的, 这一点与Linux恰恰相反

6. **关于总线的一些问题**
    - 对于I2C, SPI这类总线
        - 如果存在持续操作总线的行为, 可以保持激活设备(发送了起始信号, 或者拉低了片选信号)
        - 让所有的操作, 在一个总线事务中完成, 这样可以提高效率: 在实际的设计中, 应该如何实现这样的过程
    
7. **FatFs文件系统**
    - 崩溃1: 堆栈越界导致的崩溃
        - 移植过程中遇到了崩溃问题, 起初使用HardFault_Handler并没有查出来: 可能是程序写的不对
        - 通过临时加打印发现全局变量中的指针被清空了, 变成了NULL, 于是开始怀疑栈数据导致全局变量被覆盖: 栈向上增长

        - 需要增加一些堆栈越界检测方法
    - flash整块擦除
