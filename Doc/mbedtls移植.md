

# mbedtls开源库


## 重要概念

1. **PK: Public-Key Cryptography**: 公钥密码学
    - 非对称密码学
    - 核心组件
        - 公钥: 用于加密数据或验证签名
        - 私钥: 用于解密数据或创建签名
    - 作用: 解决对称加密中密钥分发的难题, 并实现了数字签名和身份认证

2. **PKI: Public Key Infrastructure**: 公钥基础设施, 运用PK理论建立的一套"社会信任体系"
    - 是一个完整的框架、体系结构、服务、技术和流程的集合, 目的是 __管理公钥__ 及其对应的 __管理数字身份__
    - 核心组件
        - CA: 证书颁发结构
        - RA: 注册结构, CA的前台
        - X.509: 数字证书
        - 证书库: 存储和发布证书的地方
        - 吊销检查: 检查证书是否失效
    - 作用: PKI建立一个信任链, 使得不同个体之间能够通过信任一个共同的根CA来相互验证身份

3. **PKCS: Public-Key Cryptography Standards**: 公钥密码学标准
    - RSA实验室发布的一系列标准, 定义如何实现和互操作公钥密码学的底层技术细节. 确保不同厂商开发的加密软件能够相互协作
    - 核心组件
        - PKCS#1: 定义RSA加密和签名的机制. 比如, 数据在加密前应如何填充
        - PKCS#7/CMS: 定义加密消息的语法标准
        - PKCS#8: 定义私钥信息的语法标准. 如何格式化和加密一个私钥文件
        - PKCS#10: 定义证书签发请求的语法标准
        - PKCS#11: 定义一个名为"Cryptoki"的通用接口, 用于访问安全硬件上的加密设备
        - PKCS#12: 定义一种归档文件格式, 用于将私钥及其对应的证书打包成一个加密文件, 方便备份和传输(.p12, .pfx)
    - 作用: 定义公钥密码学中基本元素的规格

4. **ECC/ECP**: 椭圆曲线密码学/原语
    - ECC: Elliptic-Curve Cryptography（椭圆曲线密码学）
    - ECP: Elliptic Curve Primitives（椭圆曲线原语）

5. **PSA: Platform Security Architecture**: 平台安全架构
    - ARM公司提出的一个整体的安全框架和一组API，旨在为基于 ARM 架构的物联网设备提供一致的安全基础
    - 核心组件
        - 标准化: 为碎片化的物联网市场提供统一的安全接口
        - 安全生命周期管理：管理设备从制造到报废整个生命周期的安全状态
        - 密码学服务：提供安全的密码学功能（如随机数生成、密钥存储、加解密），通常依赖于硬件安全特性
        - 安全存储：保护敏感数据（如 PKI 中的私钥），防止被非法提取

## 散列函数: content -> digest
1. **MD5**
    - 功能: 任意长度生成128位(16字节)的摘要, 通常以一个32位的16进制数字字符串表示
    - 现状: 已被破解
2. **SHA-1**: 输出160位, 已不安全

3. **SHA-2**: 流水线结构
    - SHA-256
    - SHA-512

4. **SHA-3**: 海绵结构
    - SHA2-224
    - SHA3-256
    - SHA3-384
    - SHA3-512

## 消息认证码: HASH(content, shared_secret) -> MAC
1. **Poly1305**
    - 功能: 使用("共享密钥", "消息")生成消息认证码, 避免消息伪造

2. **HMAC**: 基于散列的消息认证码
    - __需要选择一个散列算法__
    - HMAC-SHA256: 绝大多数应用的首选

3. **其他MAC算法**
    - CBC-MAC: 基于分组密码（如 AES）的密码块链接模式
    - GMAC(Galois/Counter Mode 的认证部分): __GCM__ 是一种 __认证加密__ 模式
    - Poly1305
    - KMAC(SHA-3/Keccak): 安全性基于 Keccak 海绵结构


## 对称加密算法

1. **AES**: aes.c, aesce.c(硬件加速), aesni.c(硬件加速)
    - ccm.c: CCM加密模式
    - gcm.c: GCM加密模式
    - AES-ECB: 密码本. 相同分块密文相同
    - AES-CBC: 以16字节为分块, 循环调用ECB, 然后明文块与前一个密文进行异或
    - AES-CFB: 错误传播有限, 流加密. 按字节加密
    - AES-OFB: 错误不传播, 流加密. 按字节加密
    - AES-CTR: 错误不传播, 流加密. 按字节加密

2. **ARIA**: aria.c
3. **Camellia加密**: camellia.c
4. **ChaCha20流加密**: chacha20.c
5. **DES和3DES**: 过时, 不安全


## 非对称加密与公钥密码学: RSA, ECC等公钥算法

1. **大整数运算**
    - bignum.c: 大整数运算的基础库
    - bignum_core.c: 大数运算的核心底层函数
    - bignum_mod.c: 模运算功能
    - bignum_mod_raw.c: 底层模运算

2. **DH: Diffie-Hellman-Merkle**: 密钥交换
    - dhm.c: DHM密钥交换
    - ecdh.c: 椭圆曲线DH密钥交换

3. **ECC: 椭圆曲线离散对数**: 更快, 密钥短
    - ecdsa.c: 椭圆曲线数字签名算法
    - ecjpake.c: 椭圆曲线密码认证密钥交换
    - ecp.c: 椭圆曲线点运算
    - ecp_curves.c: 标准椭圆曲线参数
    - ecp_curves_new.c: 新格式的椭圆曲线参数定义


4. **RSA: 大整数分解**: 更早出现, 兼容性好
    - rsa.c: RSA 加密和签名算法。
    - rsa_alt_helpers.c: 用于替代 RSA 实现的辅助函数。


## X.509证书管理
1. **证书**: 公钥证书
    - 证书, 是一个数字文件, 文件中包含一个实体的 __身份信息__ 和其对应的 __公钥__
    - 受信任的第三方机构(CA)对文件进行 __数字签名__: 计算摘要, 使用私钥对摘要进行加密

2. **X.509证书**
    - X.509证书数字文件
        - 版本号
        - 序列号: CA分配的唯一标识
        - 签名算法: CA用来签名此证书的算法
        - 颁发者: CA的名称
        - 有效期
        - 主体: 证书持有者的身份信息
        - 主体公钥信息: 证书持有者的公钥及其算法
        - 扩展信息
        - CA的数字签名: CA使用自己的私钥对证书的所有上述信息进行签名
    - X.509是标准的证书格式, 实现了全球的互操作性

3. **X.509证书格式**
    - 证书本身是 __ASN.1数据结构__
    - __DER编码__: 二进制格式. 常用于Windows系统和Java环境
    - __PEM格式__: 
        - DER证书经过Base64编码
        - 加上 __-----BEGIN CERTIFICATE-----__ 和 __-----END CERTIFICATE-----__ 头尾标记的文本文件
    - 扩展名: .crt, .cer, .pem

4. **ASN.1**
    - 本质: 是一种用于 __描述数据结构和数据表示法的国际标准__
    - 作用: 解决跨平台通信问题
        - 通信双方使用ASN.1定义交换的数据结构
        - 使用标准的编码规则, 将ASN.1描述的数据结构转换成唯一的、无二义性的字节流
    - 组成
        - 抽象语法
            - 基本数据类型
            - 结构类型:
        - __编码规则__
            - BER: 基本编码规则
            - DER: 可辨别编码规则. BER的一个子集. X.509证书使用DER编码
            - PER: 压缩编码规则
            - XER: XML编码规则
        - BER/DER使用TLV三元组编码(Type, Length, Value)

5. **获取证书**
    - 获取一个被公开信任的证书, 通常需要向 __证书颁发机构__ 购买或申请
    - 申请流程
        - __生成密钥对__: 生成一对非对称密钥
        - 生成 __证书签名请求(CSR文件)__
            - CSR包含你的公钥, 身份信息等
            - 生成CSR时, 会用你的私钥签名, 以证明你有对应的私钥: __CSR用自己的私钥签名__
            - 这样CA拿到CSR时, 会使用公钥进行验签: 解析出摘要, 与CA自己计算的只要比对
        - 向CA提交CSR
        - CA验证身份: CA会验证你对申请证书的域名或组织是否有控制权
        - CA签发证书
    - Let's Encrypt 是一个非常流行的免费 CA

6. **使用证书**
    - 证书的使用涉及两个角色: 服务端 和 客户端
    - 服务端
        - 配置: 将从CA获取的证书文件(以及可选的中间证书链)和私钥文件配置到服务器软件中
        - TLS/SSL握手过程中提供证书
    - 客户端
        - 接收证书
        - 验证证书链
            - 验证签名: 使用CA的公钥验证服务器证书是否有效. 确保是由受信任的CA签发的
            - 验证有效期, 吊销状态, 主体名称
            - 构建 __证书链__: 服务器证书通常由中间CA签发, 中间CA的证书又由根CA签发. 
                - 客户端需要一步一步验证, 直到一个它信任的根证书
                - 根证书通常预先安装在操作系统或浏览器中
        - 验证通过后: 客户端新人服务器的身份, 从证书中提取服务器的公钥, 用于后续的加密通信(如协商对称会话密钥)


## 密钥交换算法: ECDHE(基于椭圆曲线的迪菲-赫尔曼临时密钥交换算法)

1. **椭圆曲线**: 离散对数问题
    - 离散对数: 给定一个值 H, g的x次方等于H, 求x
    - 椭圆曲线: 给定一个点 G, Q = dG, 求d
    - 逆向运算非常困难

2. **密钥交换流程**
    - 协商公共参数(椭圆曲线): __基点G是所选定的标准椭圆曲线预先定义好的、公开的固定参数__
    - __生成临时密钥对__
        - C端, 生成私钥C_private, 计算公钥C_public = C_private * G
        - S端, 生成私钥S_private, 计算公钥S_public = S_private * G
        - 私钥生成过程
            - 随机数生成: 调用 __密码学安全的伪随机数生成器__
            - 生成的随机数(比如256位), 必须限制在基点G的阶n的有效范围内: 1 <= d <= n-1
            - 生成公钥: 同各国椭圆曲线, 计算公钥 Q = d * G
    - 交换公钥并认证身份: 对公钥进行签名
    - __计算共享密钥__(预主密钥)
        - S = C_private * S_public = C_private * (S_private * G)
        - S = S_private * C_pulic = S_private * (C_private * G)
    - 预主密钥 __派生会话密钥__: 将S与握手过程中的所有交换的明文消息混合(握手哈希)
        - 派生用于加密的对称密钥
        - 用于认证消息的MAC密钥
        - 初始化向量等参数

## RSA
1. **依赖文件**
    - md.c: 提供统一的散列函数接口
    - bignum: bignum.c, bignum_core.c, bignum_mod.c, bignum_mod_raw.c. 大整数计算
    - rsa: rsa.c, rsa_alt_helper.c
    - constant_time.c: 恒定时间比较函数
    - oid.c: 对象标识符数据库

2. **依赖关系**
    - md.c: RSA很少直接对原始数据进行签名或加密, 而是与哈希算法结合使用
        - 数字签名: 先生成数字摘要, 对摘要进行RSA非对称加密
    - constant_time.c: 恒定时间编程, 防止旁路攻击, 尤其是定时攻击
        - __定时攻击__: 攻击者通过精确测量算法执行所花费的时间, 来推断出秘钥信息
            - 如果RSA操作的执行时间依赖于私钥的位值或明文内容, 那么攻击者可通过大量测量来恢复私钥
        - 恒定时间变成
            - mbedtls_ct_memcmp: 用于比较两个字符串, 无论结果如何, 执行时间都相同
            - mbedtls_ct_uint_mask: 生成一个输入掩码, 用于在不引入条件分支的情况下实现条件选择操作
    - oid.c: __算法的标识和编码__, 主要用在处理数字证书、签名算法标识等场景
        - 在 X.509 证书、证书签名请求或 PKCS#1 等标准中
            - 使用一个叫做 __对象标识符__ 的 __国际标准号码__ 来标识"RSA-SHA256"签名算法
        - oid.c维护了一个庞大的OID数据库, 并提供了查询功能, 它将OID值转换为可读的字符串描述, 或者反向转换
